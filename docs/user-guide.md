# 后台操作手册

## 1. 登录后台

浏览器访问部署地址，例如：

```text
http://172.26.80.101/
```

默认管理员：

```text
账号：admin
密码：admin123456
```

首次上线后请立即创建新管理员或修改默认密码。

## 2. 后台菜单

登录后左侧为后台菜单，系统会按账号角色显示可用模块：

- 饭票管理：查询、分页浏览、作废、导出饭票记录。
- 饭票生成：按用餐人数和餐别批量生成饭票。
- 扫码核销：饭堂工作人员扫码或粘贴 token 后核销。
- 系统设置：维护系统公网地址、企业微信参数和审批字段映射。
- 权限管理：维护后台账号、角色、部门和企业微信 UserID。

## 3. 系统设置

管理员登录后，进入“系统设置”。

基础设置：

- 系统公网地址：员工饭票链接和扫码核销链接使用的地址。
- 系统时区：默认 `Asia/Shanghai`。
- 票面公司名称：企业微信二维码图片顶部显示的公司名称。
- 票面版权声明：企业微信二维码图片底部显示的版权和联系人信息。

企业微信应用：

- CorpID
- AgentID
- Secret

审批回调：

- Token
- EncodingAESKey
- 审批模板 ID

审批字段映射：

- 用餐日期字段名
- 餐别字段名
- 用餐人数字段名
- 部门字段名
- 申请原因字段名

保存后立即生效，不需要重启容器。

## 4. 生成饭票

进入“饭票生成”：

1. 填写员工姓名。
2. 可选填写企业微信 UserID 和部门。
3. 选择用餐日期。
4. 填写用餐人数。
5. 多选餐别，可同时选择早餐、午餐、晚餐。
6. 点击“生成饭票”。

系统按“用餐人数 x 餐别数量”生成饭票，确保一人一餐一码。例如 2 人选择早餐、午餐、晚餐，会生成 6 张饭票。

## 5. 权限管理

管理员进入“权限管理”后，可以新增或编辑账号：

- `admin`：系统管理员，可维护设置、账号和全部业务。
- `hr`：行政制票，可生成、查询、作废、导出饭票。
- `verifier`：饭堂核销，只能进入扫码核销功能。
- `auditor`：行政查看，只能查询和导出报表。

饭堂工作人员只分配 `verifier`；行政核实人员只分配 `auditor`；需要制票的行政人员分配 `hr`。

## 6. 核销饭票

饭堂工作人员需要具备 `verifier` 角色。

手机登录后只显示核销入口：

- 使用手机相机、微信或企业微信扫一扫饭票二维码。
- 扫码后会打开核销链接，系统自动预览并核销。
- 核销成功显示绿色结果，失败或重复核销显示红色结果和具体原因。
- 系统会校验饭票状态、用餐日期、餐别核销时间段和过期时间。

注意：当前核销方式不依赖网页调用摄像头，HTTP 环境下也可通过手机系统相机或微信扫一扫打开核销链接。生产环境仍建议配置 HTTPS，提升访问安全性。

## 7. 行政核实

进入“饭票管理”，可按员工姓名、UserID、部门、饭票编号、审批单号和状态筛选。列表支持分页，可切换每页 10、20、50、100 条。

行政制票人员或管理员可勾选多张饭票后点击“批量作废”。已核销饭票不会被作废，系统会自动跳过。

点击“导出”，系统会下载 `meal-tickets.xlsx`，用于行政核对饭票使用情况。

## 8. 企业微信联调

企业微信审批回调地址：

```text
http://sec-agent.poly-energy.com:18001/api/wecom/callback/approval
```

审批通过后，系统会：

1. 接收企业微信审批状态回调。
2. 验签并解密回调消息。
3. 判断审批状态是否为通过。
4. 拉取审批详情。
5. 读取申请人姓名和部门信息。
6. 读取用餐人数和多选餐别。
7. 按一人一餐一码生成饭票。
8. 生成带用餐信息的二维码票面 PNG，并通过自建应用发送给申请人。

参数未齐全时，可用明文 JSON 先测试业务链路，示例见 `docs/production-setup.md`。
